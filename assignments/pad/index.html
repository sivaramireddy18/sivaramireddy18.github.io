Case Study 2 — Dual issue & register renaming

The analysis demonstrates how independent instructions can occupy different functional units concurrently, while physical-register renaming removes false name dependencies. Reorder-buffer style commit preserves architectural program order.

Issue width: 2 Example: independent multiplier + integer-ALU work may issue together. Rename: architectural R1 → physical destinations P1, P2, ... Commit: results retire in program order.

Engineering trade-offs

  • More hardware structures can increase area, power and verification complexity.
  • Parallel execution is useful only when work is sufficiently independent.
  • Pipeline optimization must consider latency, forwarding and stall behavior.
  • Better prediction trades hardware cost for fewer control-hazard penalties.
  • For embedded systems, deadline compliance matters in addition to average throughput.
